# Plan for #3: Add DELETE /api/runs/:id

## Goal
Test engineers can delete a recorded run by id. Deleting removes it from `GET /api/runs`
(204 No Content), an unknown id answers 404 in the existing error shape, and a run whose
`status` is `"running"` cannot be deleted (409 with `error: "run is in progress"`). Nothing
about `GET`/`POST /api/runs` behavior changes.

## Dependencies (confirmed / plausible / open)
- **confirmed**, change: yes — `src/runs.ts` `RunStore`: no `delete` method exists today
  (only `list`, `get`, `create`). Add `delete(id): "deleted" | "not-found" | "in-progress"`
  (or similar) that checks `status === "running"` before removing from the `Map`.
- **confirmed**, change: yes — `src/app.ts`: add `app.delete("/api/runs/:id", ...)` handler
  that maps store outcomes to 204 / 404 `{ error: "run not found", id }` (same shape as the
  existing `GET /api/runs/:id` 404) / 409 `{ error: "run is in progress" }`.
- **confirmed**, change: yes — `test/app.test.ts`: add three cases (success + gone from list,
  unknown id 404, running-status 409).
- **confirmed**, change: yes — `README.md` API table (lines 44-49): add a
  `DELETE /api/runs/:id` row documenting 204 / 404 / 409.
- **confirmed**, change: no — `src/config.ts` / `k8s/configmap.yaml`: no env var involved.
- **plausible**, change: no — `public/index.html`: page only lists and creates runs, no
  delete UI/button today; ticket's "done when" criteria are API-only, so out of scope unless
  you want a delete action added. Verify: grep of `index.html` shows no delete-related markup.
- **open**: how do unit tests put a run into `status: "running"` to exercise the 409 case?
  `RunStore.create` always sets `status: "planned"` (`src/runs.ts` line 71) and there is no
  status-transition endpoint yet — that's issue #6 (`PATCH /api/runs/:id/status`), not
  implemented. See open question 1.

## Tests
- `test/app.test.ts`, new cases under `describe("runs api")`:
  - delete an existing (non-running) run → 204, then confirm it is absent from
    `GET /api/runs`.
  - delete an unknown id → 404 with `{ error: "run not found", id }`.
  - delete a run with `status: "running"` → 409 with `{ error: "run is in progress" }`
    (needs the mechanism from open question 1 to set up the fixture).

## Environment contract
Not touched. No new/changed variables in `src/config.ts`; `k8s/configmap.yaml` and README env
table unaffected.

## Risks
- Route order in `src/app.ts`: `DELETE /api/runs/:id` must not conflict with existing routes;
  low risk since Express matches by method + path.
- In-memory store only (`AGENTS.md`): a delete is permanent for the process lifetime, no
  rollback — acceptable per existing "no database in this sandbox" design.
- Pipeline: unit tests only; no route/schema change affecting rollout, smoke test (`/health`),
  or Playwright browser tests (page doesn't expose delete), so deploy/browser steps are low risk.
- If the running-status fixture requires adding a store method beyond what's needed for
  production code (e.g., a setter used only by tests), keep it minimal and justify it in the
  PR per the "no new dependency without explanation" spirit for scope creep.

## Open questions
1. There's no existing way to create a run with `status: "running"` (that lands with issue #6,
   not yet implemented). To test the 409 case now, should I:
   (a) add a minimal test-only way to set a run's status directly on `RunStore` (e.g. exported
       constructor option or a small internal setter), scoped narrowly and noted in the PR, or
   (b) seed a `"running"` run via the `RunStore` constructor by extending `NewRun`/seed data
       to optionally include `status`, or
   (c) something else you'd prefer?
2. Should the delete capability also be exposed in `public/index.html` (a delete button per
   row), or is this ticket API-only as its "done when" list suggests?

## Decisions
1. Use option (b): extend `NewRun`/seed data to optionally include `status` (defaulting to
   `"planned"`), so a test can construct a `RunStore` seeded with a `"running"` run directly.
   Reuses the existing `new RunStore(seed)` pattern instead of adding a test-only setter.
2. API-only, per the ticket's "done when" list. `public/index.html` is not changed; no delete
   button is added.
